The Plan-and-Delegate Loop

One planner, cheap writers, a read-only judge: an agent workflow that only ships verified code

Abstract. We describe plan-and-delegate, a Claude Code skill in which an expensive model plans and verifies while cheaper models do the typing. Opus reads the code and proposes numbered steps, each naming its files and the check that proves it done. A DeepSeek model edits the files in place, one step at a time; GLM-5.3 reviews the diff without being able to change it; Opus then runs the real build and tests. A step that fails is sent back once with its errors, a second failure triggers diagnosis instead of a third guess, and nothing is committed or pushed until the human sees the evidence and says yes.

1Method

The human types one command naming the task. Opus reads the code and answers with a numbered plan; each step lists the files it may touch and the command that proves it done, and nothing runs until the plan is approved. Opus then writes a self-contained brief per step, since the worker cannot see the conversation. The worker edits files in place but is denied every shell command, so git and tests stay with Opus. The diff goes to GLM-5.3 as text, to report bugs and never edit.

Table 1. Rules the loop works under.

RuleIn practice
Clean startcommitted tree first; one command undoes a step
One writersteps run in order, never in parallel
Read-only judgeGLM-5.3 reads the diff; cannot edit or run
Evidencereal build and test output, never “it works”
Two gateshuman approves the plan and the push, nothing else

2Why the split matters

Each role closes a loophole. A writer that cannot run commands cannot quietly commit, push or delete. A reviewer that cannot edit cannot “fix” a finding by hiding it. And because the planner also verifies, the model that promised a check is the one that has to show it passing.

3The human moves up a level

Nobody types the boilerplate any more. The human’s work moves into the task and two decisions: is this the right plan, and is this evidence enough to ship. Rust is the exception: when learning is the point, Opus asks before delegating.
